SECTION 01

Why Zaahi Designs Needs SEO Work

Zaahi Designs is a beautifully built storefront. The design is elegant, the store is secure, it loads quickly on the server side, and it already runs a Facebook Pixel and a WhatsApp booking flow. The problem is not the shop customers see — it is what search engines and AI assistants see, which is almost nothing. The store is built as a JavaScript-rendered single-page app, so when Google or an AI crawler first requests the page, it receives a nearly empty shell with a 13-character title and no description. Everything that sells — the collections, the product copy, the headings — arrives a moment later, after the crawler has already formed its impression. That single architectural choice is behind most of the findings in this report, and the good news is that it is fixable without rebuilding the store.

📄

The page source is nearly empty for search engines

The raw HTML that crawlers read contains a title and a tracking pixel — and little else. The "Elegance Woven In Tradition" hero, the collections and every product only appear after the browser runs the site's script. Search engines see the shell first and often index that.

🔍

The strongest ranking signals are missing

There is no meta description, the title is just "Zaahi Designs" (13 characters), and no heading structure is present in the source. These are the first things a search engine looks for to understand and rank a page, and right now they are blank.

📱

Mobile load speed is in critical territory

Mobile scores 45 with a Largest Contentful Paint of 16.8 seconds — well over six times Google's 2.5-second target. For a fashion store where most browsing happens on phones, that delay quietly costs sales before a shopper ever sees a dress.

🔗

No links and no backlinks to build authority on

The homepage source shows no internal links between collections and no external links, and the domain currently has no recorded backlinks. Search engines have very little to crawl and no authority signals pointing in — so even great products stay invisible.

SECTION 03

The Rendering Problem Explained

This is the most important section of the report, because one issue explains most of the others. When we requested the homepage the way a search engine does, the served HTML contained the title and a tracking pixel — and essentially no visible content. Everything a shopper sees is assembled a moment later by the store's JavaScript. A modern browser handles that fine. Search-engine and AI crawlers often do not, or they judge the page before the content arrives. That is why the audit reports thin content, no headings and missing keywords even though the live store is full and elegant.

👁

What a shopper sees

A polished storefront: the "Elegance Woven In Tradition" hero, collections, product tiles, prices in AED, and a WhatsApp button — all loading quickly in the browser.

🤖

What a crawler sees first

A near-empty page: the title "Zaahi Designs", no description, no headings, and no product text — because that content only exists after the script runs.

!
Why this matters more than any single tag
Technical SEO · Root Cause
CRITICAL

Fixing the title or adding a description helps, but if crawlers still receive an empty shell first, those wins are limited. The highest-return move is to make sure the important content — headings, product names, descriptions, prices — is present in the HTML that is served, before any script runs. This is usually done with server-side rendering, pre-rendering, or a rendering service, and it makes every other on-page fix in this report far more effective.

Goal: when the page is requested, the served HTML already contains the H1, collection names, product titles, descriptions and prices — not just an empty container that a script fills in later.
THE PROBLEM
  • Crawlers receive a near-empty HTML shell
  • Rendering was measured at an extreme level (~831%)
  • AI assistants generally don't run heavy scripts, so they miss the content
  • Thin word count, no headings, no keywords on crawl
THE FIX
  • Serve pre-rendered or server-rendered HTML for key pages
  • Ensure H1, product names, copy and prices are in the source
  • Keep the current fast, app-like experience for shoppers
  • Re-test with a crawler view to confirm content is visible

Specific Improvement Opportunities

Save 3.2s
Reduce unused JavaScript

The single biggest opportunity. Splitting the code so each page only loads the script it needs — and deferring the rest — recovers the largest chunk of mobile load time.

Save ~1 MB
Compress and convert images to WebP

Images make up roughly 2 MB of the 3.05 MB page and are currently served with no compression. Converting to WebP and compressing cuts payload 25–50% with no visible quality loss.

Save 0.6s
Avoid multiple page redirects

The audit flagged redirect chains adding load time. Pointing links and resources straight at their final URLs removes an easy delay.

Minify
Minify the remaining JavaScript bundle

One JavaScript file (the main app bundle) is flagged as un-minified. Minifying it reduces download and parse time on every visit.

Lazy-load
Lazy-load below-the-fold images

Load product images only as the shopper scrolls to them, so the first screen paints faster and the browser does less work up front.

No Product or Business Schema (Structured Data)
Advanced SEO · Rich Results
HIGH

No Schema.org markup was found. For an online store this is a big miss — Product schema unlocks price, availability and rating cards in search, while Organisation and LocalBusiness schema help Google and AI assistants confidently identify and recommend the brand.

Add Product JSON-LD (name, image, price in AED, availability) to product pages, plus Organisation and LocalBusiness schema with the Dubai address and contact details.
IMPACT
  • No price or product cards in search results
  • Harder for AI assistants to recommend the store
  • Lost visibility versus schema-equipped competitors
THE FIX
  • Add Product schema to every product page
  • Add Organisation + LocalBusiness schema
  • Validate the markup after publishing

Publish an XML sitemap listing every collection and product, reference it in robots.txt, and ensure real, crawlable links connect the homepage to collections and products.

8
No Canonical Tag — Filter URLs Risk Duplication
Advanced SEO · Duplicate Content
MEDIUM

No canonical link tag was found. The store uses filter URLs such as /collections?filter=featured and /collections?filter=new-arrivals, which can create several URLs showing similar content. Without a canonical tag, search engines may split ranking signals across them.

Add a rel="canonical" tag to every page pointing to its preferred URL, and canonicalise filtered collection views back to the main collection where appropriate.
IMPACT
  • Duplicate-content confusion from filter URLs
  • Ranking signals split across near-identical pages
  • Wasted crawl budget on variations
THE FIX
  • Add canonical tags to all pages
  • Point filtered views to the main collection URL
  • Keep one clear primary URL per product

Add Open Graph and X Card tags with a branded preview image, title and description so shared links show an attractive product card everywhere.
